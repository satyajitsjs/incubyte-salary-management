# Suggested Incremental Commit Narrative

Use small, truthful commits as you run/review the project. Do not squash them before submission.

1. `docs: define salary management MVP requirements`
2. `docs: record architecture and trade-off decisions`
3. `chore: scaffold Django API and Next.js UI`
4. `feat: model employees and normalized compensation`
5. `test: cover compensation validation and salary history`
6. `feat: add searchable paginated employee API`
7. `feat: add compensation analytics endpoints`
8. `test: cover filtering and aggregate reporting`
9. `feat: add deterministic 10k employee seed command`
10. `feat: build HR dashboard and employee directory`
11. `feat: add salary editing and history UI`
12. `feat: add transactional CSV import workflow`
13. `test: cover CSV validation and duplicate handling`
14. `chore: add Docker and deployment configuration`
15. `docs: document AI workflow performance and demo`

The ZIP includes a starter Git history, but after reviewing/running it locally you should continue with your own truthful commits for any changes, deployment fixes, clarifications, and demo polish.
